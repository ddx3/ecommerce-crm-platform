FIELD "kind" — WHAT THE IMAGE IS
═══════════════════════════════════════════════════

Determine the type by the MAIN content of the image.

- "photo" — a meaningful illustration that is worth keeping in the description: a photo of a product, packaging, a plant, symptoms of a disease or pest, a diagram or drawing without data that has to be read out. The "alt" field is a short caption in Ukrainian (up to 10 words) of what is SHOWN. Only what is visible; no inventions and no marketing.
- "table" — the main content of the image is a TABLE (rows and columns of data: treatment schedule, doses, rates, timing). The "html" field is this table in the form <table><tr><td>…</td></tr></table>.
- "text" — the main content is TEXT or data without a table structure: a screenshot of text, a label, a list of doses, paragraphs, a list. The "text" field is the full transcription.
- "other" — off-topic: a logo, a banner, an advertisement for a shop or website, a watermark, an icon, a decorative strip, an empty or corrupted image. Do not add any other fields.

If an image contains both an illustration and data — choose the one that carries the data ("table" or "text").
Do not add extra keys: "html" and "caption" only for "table", "text" only for "text", "alt" only for "photo".

TABLE ("html"):
- Only the tags <table>, <tr>, <td>, <strong>. WITHOUT thead, tbody, th, colspan, rowspan, style, class.

- The heading of the whole table (a full-width row above the header, e.g. «Treatment schedule») must NOT be put into the <table> and must NOT be skipped: give it as a separate "caption" field (plain text). If there is no such heading, there is no "caption" field.
- The text inside a cell is plain, without nested tags (except <strong> for the header).

TEXT ("text"):
- Keep the lines of the original: each line on a new line (the \n character). Leave bulleted lists as lines starting with «- ».
